# Methods (70)

> Part of ULTIMATE SEO/GEO/AEO/AIO AUTOBOT. Generated from the Search Ops export (`methods`). Skill names are mapped to staged slugs.


| id | Name | Rule | Mechanics |
|---|---|---|---|
| `output-first` | Output-first, never an audit PDF | Every run has to end in a file someone can merge, send, or publish. | Each skill declares its shipped artifact up front; if the run produced only findings, it is not finished. |
| `state-in-repo` | State lives in the repo | `seo/` is the memory; a fresh session must be able to resume from it. | context, log, backlog, and one file per artifact family; raw connector pulls go in `seo/<site-slug>/data/` untouched. |
| `serp-intent-lock` | SERP intent lock, pre-write | Decide the page format from what actually ranks before writing a word. | Read the live top ten for the target term, infer the dominant format and entities, write the lock file, then draft to it. |
| `url-overlap-clustering` | Cluster by URL overlap, not semantics | Two keywords belong together only if the same pages rank for both. | Pull live results per keyword, cluster where the URL sets overlap, so pages never compete with each other. |
| `value-not-volume` | Value filter: click cost times demand | Volume alone lies; rank opportunities by what a click is worth. | Multiply cost-per-click by volume, keep the head where both are real, and match format to intent. |
| `consensus-plus-proof` | Consensus plus proof | Agree with the field, then add what only the operator can show. | Mark each section as consensus (citable common ground) or proof (first-hand receipt); a post with no proof section is commodity. |
| `proof-card` | One fact, one card | A proof card carries one atomic claim, its method, its raw numbers, and its failure note. | Benchmarks, customers, numbers, and workflows each get an id; pages cite ids, never prose drift. |
| `route-fact` | Route a new fact everywhere it belongs | A new number lands on every page that already claims it, in the same pass. | Index pages by proof-card id, then sweep and update each match, reporting what changed. |
| `forty-word-answer` | Answer in the first forty words | Answer engines quote openings; the direct answer goes first, unqualified. | First paragraph answers the title question in plain declarative prose, then the article expands. |
| `question-headings` | Question-shaped headings | Headings phrased as the question a buyer types, one answer each. | Each section is self-contained and quotable without its neighbours. |
| `slop-table` | Twenty-pattern slop pass | Strip the tells that mark a draft as machine-made, in place, without rewriting the author's voice. | Run the checklist before and after; the check exits clean or the pass is not done. |
| `hook-spike-payoff` | Hook, spike, payoff | Open with the tension, spike it, pay it off — explanation is not selling. | Applies to heroes, subject lines, cold emails, social hooks, and result titles alike. |
| `seat-math` | Real seat math | Compare at one, five, and twenty-five seats with the buyer's actual usage. | Use published prices only; a comparison that wins at one seat and loses at twenty-five says so. |
| `ten-minute-switch` | Ten-minute switch steps | A comparison page converts on the migration, not the feature matrix. | Numbered steps a buyer can finish in one sitting, with what breaks and how to check. |
| `verified-triggers` | Verified switching triggers only | A trigger goes on the page only after it is verifiable in public and still true. | Each claim gets a source and a date; stale or unverifiable triggers are cut. |
| `send-cut` | SEND / CUT prospect table | Every prospect is judged before a draft is written. | Table with the target URL, the fit, the ask, and the reason to cut; only SEND rows get drafts. |
| `ask-first` | Ask first, reward second | The email asks for judgement, not a favour. | Short, plain text, one specific page, an easy no; no template smell, no flattery blocks. |
| `variety-matrix` | Structural variety across a batch | No two emails in a batch share a skeleton. | Vary opening, ask, evidence, and close independently so clones never arrive in the same inbox twice. |
| `upper-forty-anchors` | Anchors from the upper forty percent | Link equity flows from the posts that already earn traffic. | Rank posts by traffic, place contextual anchors in the top band, and leave navigation out of the count. |
| `traffic-to-money` | Traffic-to-money routing | A blog that ranks but never links to the money page is a cost, not an asset. | Audit inbound contextual links per money page, inject where intent matches, report before and after. |
| `one-hop-union` | One-hop redirect union | Every old URL gets exactly one hop to exactly one new URL. | Union the old URL list with the backlink target list so no link lands on a 404; chains are the killer, not the map. |
| `verify-redirects` | Verify the map, not the config | A redirect is done when a request proves it. | Checker requires a 301 or 308, a Location equal to the mapped URL, at most one hop, and a final 200; print pass and fail counts. |
| `real-authority` | Judge the link, not the score | A high domain score on a page nobody visits is worth nothing. | Open the actual linking page, check topical fit and traffic, and flag the fakery before outreach. |
| `wave-cascade` | Five-wave directory cascade | Order submissions by what makes the next one easier: entity verification first, galleries last. | One manifest reused across registries; waves run from review sites to curated galleries, tracking status per site. |
| `six-phase-refresh` | Six-phase refresh | A slipping post is diagnosed against the current top ten, not rewritten from taste. | Audit, competitor read, gap table, outline, approval, then rewrite; the gap table is the artifact that justifies the edit. |
| `one-page-sprint` | One page, thirty days | Concentrate fixed effort on a single page until it moves. | One money keyword, one page, a daily ritual of small edits, links, and proof; new pages wait. |
| `fatal-first` | Fatal first, fluff never | Nothing cosmetic ships while a crawl, indexation, or visibility blocker stands. | Six-point decision procedure ordered by revenue, each with a verifiable before and after. |
| `key-moments` | Chapters as searchable steps | Timestamps name the sub-step a searcher wants, not the section of the video. | Open at zero, every chapter at least ten seconds, phrased as the query. |
| `video-embed` | Video schema on the matching post | A video that exists off-site earns nothing; the post carries the structured data. | Structured video markup plus the transcript-derived summary on the page that ranks for the topic. |
| `image-budget` | Image weight is a ranking input | Cover and inline images stay under a hard byte ceiling and carry descriptive filenames. | Compress to the ceiling, read the file back to confirm it renders, and describe it in the alt text with real subject matter. |
| `six-layer-firewall` | Six-layer bot firewall | Block the scrapers, keep the crawler that sends traffic. | Serve a real page instead of an error, verify the good crawler by network identity rather than user-agent, prove the session, publish the directive, cache the public routes, then red-team it. |
| `reddit-gates` | Four gates before a Reddit reply | The thread must already rank, be unlocked, fit the subreddit's rules, and allow the reply to be useful. | Check each gate, then write as a practitioner; the queue file records the dropped threads and why. |
| `privacy-audit` | Privacy audit before syndication | Third-party platforms scrape public fields harder than the site does. | Scrub personal names, addresses, and private customer detail from every field, then re-read the bundle. |
| `buyer-decision-first` | Buyer decision before keyword | Start from the decision a buyer makes, then derive the words and the prompts. | List the decisions (do I need this, which type, which vendor, is it worth it, how hard is setup, what do others say), write 20-40 real questions under them, and give every question two tracked forms: search terms and a full-sentence prompt. |
| `lost-prompt-buckets` | Four buckets, checked in order | Diagnose before creating. Nothing gets written until the cause is named. | Crawl or index problem fixes first, then weak page (refresh, never duplicate), then missing page (the only bucket that earns a new URL), then off-site gap. Name a second bucket when one applies. |
| `refresh-not-duplicate` | Refresh, do not duplicate | If a page is already the right home for the question, the fix lives on that page. | Before any brief, check whether a page already aims at the question; an existing page becomes a refresh row on the board, not a new article. |
| `own-claim-earn-contest` | Source sorting: own, claim, earn, contest | Which source shapes this specific recommendation, and why is the competitor better represented there? | Own: pages you control, fix or add. Claim: profiles you can take over, claim and match the facts. Earn: editorial and community mentions, make yourself worth including. Contest: wrong information, request the correction with evidence. |
| `measure-separately` | Never merge the two systems | Search rankings and answer-engine mentions are separate measurements with separate verdicts. | Record position, clicks, mentions, citations, and cited sources per prompt; report non-branded rows on their own; a page can rise in one system and vanish in the other. |
| `one-change-rerun` | One change, then rerun the same prompts | A fixed prompt set plus one change at a time is the only version of this that proves anything. | Log the change with the prompts it targets, rerun on schedule, give each change a verdict (worked, no change yet, hurt), and double down on what moved real users. |
| `quotable-page` | Built to be quoted | A page wins answers by being liftable: direct answer first, plain numbers, a definition, a table, sourced claims. | Answer the main question in one paragraph above the fold, keep numbers unattributed to nothing, and publish claims a reader can check. |
| `brief-not-article` | Brief, do not write | The deliverable to a writer is a brief with the angle, the outline, the proof needed, and the links. | Confirm the target and whether it is new or a refresh, read the current top results and the answer, then hand over angle, outline with a line per heading, proof gaps, internal links both ways, two titles, two descriptions, and the one thing that makes it best. |
| `rank-by-buyer-demand` | Rank technical work by buyer demand | A crawler warning on a page nobody buys from is noise. | Order fixes by whether they touch a page tied to a real buyer question, not by the count of site-wide warnings. |
| `image-six-points` | Six image checks, measured not guessed | An image is either measured or reported unmeasured; never scored from memory. | Descriptive hyphenated filename; compress to WebP/AVIF at display width with width and height set; alt text that describes the image with the term only where natural, empty for decorative; ImageObject schema on product, licensed, and key editorial images; original over stock, and flag stock that competitors use; captions where they clarify. Plus: real img elements with a src, and lazy-loading below the fold only. |
| `agent-surface` | The agent surface is a published contract | Agents read files and endpoints, not screenshots. If it is not published, it does not exist to them. | Crawlability and clean HTML first, then validated structured data, then the files agents fetch (a plain-text index, an llms.txt, a well-known discovery document, a server card), then a real MCP endpoint, then bot access rules at the edge that keep the good crawler. |
| `probe-covers-criteria` | A probe must cover every route the rule names | A pass that skips the pages the criterion named is a defect, not proof. | Sample every route in the criterion, quote status codes and counts, and treat a partial sweep as a fail. |
| `measure-before-after` | Measure before and after with one deterministic instrument | A fix is real when the same instrument, run the same way, moves. | One command, no browser and no model in the scoring path, byte-stable output; run on production before and after, quote the closed rows and the delta rather than a feeling. |
| `retrieval-before-content` | Cited when searched | A page is cited only if the engine's own search retrieved it; win the sub-queries before touching the prose. | Collect the sub-queries from first-party grounding data and visible search steps, map each to a passage on an existing page, and fix buried or absent answers there. One section per sub-query, never one page per sub-query. |
| `named-when-remembered` | Named when remembered | Unprompted brand mentions come from what the model already knows, not from the page it just fetched. | Keep one canonical fact sheet, make every owned, claimed, and reference source match it, and earn co-occurrence with the category phrase on third-party pages. Track the non-branded mention rate and branded-query demand as the two memory signals. |
| `passage-is-the-unit` | The passage is the unit of citation | Engines lift a paragraph, not a page; each buyer question gets one paragraph that survives being lifted. | Question as heading, answer in sentence one with the subject named in full, 75 to 150 words, number with unit and date inside it, no cross-references. Detail follows the paragraph, it does not replace it. |
| `rate-not-rank` | A rate with its n, never a rank | AI answers are sampled, so one run is an anecdote and a position is noise. | Fixed prompt clusters, recorded conditions, at least 30 runs per cluster per engine before a rate is reported, a 95% interval on every rate, and a verdict only when intervals separate or two samples agree. |
| `first-party-first` | Platform numbers first, each with its definition | The platforms now report their own AI numbers; those lead, and third-party scans are a labeled second opinion. | One dated ledger for Search Console AI impressions, Bing citations and grounding queries, assistant business-profile insights, and the analytics assistant channel. Each metric sits beside its definition and window and is never summed with another. |
| `per-engine-plan` | One plan per engine | Each answer engine draws on a different part of the web and changes its mix inside a month. | Build the off-site plan from the user's own sampled citations per engine, date it, re-check monthly, and never average visibility across engines. |
| `earned-over-placed` | Earned beats placed | Answer engines overwhelmingly cite pages the brand neither owns nor paid for. | One first-hand data asset with a checkable method on the owned domain, pitched to the outlets already cited for the tracked prompts. Paid and contributor placements are cut when the purpose is ranking or citation value. |
| `indexable-or-it-did-not-happen` | A placement counts only if it is meant to be found | A third-party page that is noindexed, blocked, or uncrawlable by the target engine is not coverage. | Before counting or buying a placement, read its robots meta, `X-Robots-Tag`, robots.txt, and whether the outlet blocks the engine's crawler. Shareable and tool-generated pages are assumed noindexed until proven otherwise. |
| `inclusion-is-a-setting` | Inclusion is a setting before it is a content problem | Check every control that can exclude the site before diagnosing the copy. | Read the search AI control on every property and its parents, snippet directives, per-bot robots rules, and edge bot settings. Report the state as found; change nothing without approval. |
| `verify-the-bot` | Verify the bot, not the user-agent | A user-agent string proves nothing in either direction. | Evidence in order: the edge provider's verified-bot field, published network ranges, request signatures. A spoofed-agent curl is a hint only, and every unverified count is labeled unverified. |
| `three-copy-parity` | Feed, markup, and page agree | An agent trusts the offer only when the feed, the structured data, and the visible page say the same thing. | Sample products, compare identifier, price, availability, variant, shipping, and returns across the three, name the drift source, and fail the build on a price or availability mismatch. |
| `three-view-agreement` | Screenshot, DOM, and accessibility tree agree | A browsing agent acts on what its three views of the page agree on. | Walk each task in all three views, remove ghost overlays, use real links and buttons with bound labels, keep the action in the same place across templates, then publish the manifest and rerun. |
| `preflight-volume` | Volume plays pass a gate before they ship | Anything shipped in a batch is tested against the live spam policies first. | Per page: purpose, difference, proof, fit, count, consolidation. PASS, FIX, or HOLD with the reason; a batch with a HOLD ships only its passing pages. |
| `annotate-then-compare` | Annotate first, compare like with like | A number that crosses an update, a model switch, or a reporting change is two different numbers. | Keep one dated annotations file for confirmed updates, default-model changes, platform reporting changes, and shipped site changes. After an update, wait a full week past completion and compare with the week before it began. |
| `three-layer-attribution` | Provable, claimed, dark | AI-driven demand is reported in three separate layers and the dark one is never estimated into the others. | Provable: assistant-referred sessions and joined conversions. Claimed: platform-reported clicks and impressions with their definitions. Dark: no-referrer visits, narrowed by deep-page Direct landings, user-triggered fetches, and a self-reported field. |
| `logs-are-ground-truth` | Logs record what machines did | A crawl simulation says what could happen; the access log says what did. | Classify bot classes, mark verification level, then report reach on money pages, status mix, rendered-only content, requested-but-missing URLs, and wasted fetches. Fix access before copy. |
| `dated-platform-facts` | Platform facts expire | Any statement about a platform feature, policy, or protocol carries the date it was read and is re-fetched before it is quoted. | Skills read the live page at run time, update the dated register in the same pass, and let the live page win over the register and over memory. |
| `format-follows-citation` | Match the format the engine cites | When the cited sources for a question are videos or posts, another article is the wrong asset. | Mark each tracked question with the share of runs citing video or social per engine; brief a video only where it recurs and there is real proof to show, and report it on its own line. |
| `normative-score-separation` | Normative scorecards stay separate | AgentReady conformance, Websmith check results, ARI-100 and outside scores are not one metric. | Run the exact normative IDs and applicability; mark estimates ESTIMATED; retain per-instrument evidence and raw counts. Never average scores. |
| `intentional-exception` | Business intent beats a generic score | A deliberate gate or region restriction is EXCEPTION, not a defect to fix. | Record the choice, reason, and trade-off; lock the never-see list before drafting agent files; never expose wholesale prices to improve a grade. |
| `list-only-mcp-boundary` | List-only MCP audit boundary | Discovery is not permission to call a tool. | Only initialize and list/discover in audit mode. One tools/call needs explicit approval for that exact read-only call; scanner POSTs and public scores need a separate per-domain yes. |
| `live-source-hierarchy` | Live source hierarchy and host currency | Production beats a branch, deploy stamp, docs, or another bot's report. | One canonical host of record; production response > analytics/logs > backend > repo main > docs. Re-drop only on change; wrong-host run is void. |
| `proof-bind-audit` | Visible proof and schema bind | A proof link in schema is not proof the visible product points at the same document. | Fixed product sample records schema proof URL, visible proof URL, response, and MATCH/MISMATCH/NO_PROOF. Universal claims without a bind go to owner review, never copied into public claims. |
| `measured-only-dimension-score` | Score only what you measured | A 0-100 dimension score uses measured checks only; unmeasured checks are excluded and listed, never guessed. | Each measured check is pass 1, warn 0.5, or fail 0. Fewer than three measured checks means the dimension is unscored. Overall is the average of scored dimensions only. Every finding has P0/P1/P2, a dimension, an evidence URL, and a fix. These scores stay separate from AgentReady, Websmith, and ARI-100. |
