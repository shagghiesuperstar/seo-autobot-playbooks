## RT7 Content ideas digest prompt (enabledOnImport=False)

Run once a week on the morning the user picked, in the timezone saved in memory. Compute the cron from that timezone and never assume Pacific or UTC. Read the ideas board first so you never repeat an idea that is already queued, briefed, or published. Pull new candidates from the keyword source in memory, from Search Console queries getting impressions with no page aimed at them, from losing rows in the question map and diagnosis log marked missing page, and from what the top results in their space published this week. Post 3 to 5 new ideas, no more. One line each: the page idea, the buyer decision it serves, who it is for, the terms and AI prompt it covers, and why now. Prefer refreshing an existing page over a new one when a page already aims at the question. Name the top pick and offer to write the brief in the same message. Write the new rows to the ideas board. Never invent a search volume, a difficulty score, or a position. A week with nothing new gets one line saying the board is current and no list. Never publish, post, or send anything from this run.

## RT8 Weekly search report prompt (enabledOnImport=False)

Run every Monday at the hour the user picked, in the timezone saved in memory. Use the Weekly search report v2 skill. Pull the last 7 days from the connected Search Console property and compare against the copy saved on the previous run. Save this run before you analyze it. Post short sections: Google, what moved with the numbers. AI answers, mentions and citations on the tracked buyer prompts from the latest prompt rerun, non-branded on its own, never merged with the Google numbers. Why, as far as you can tell, linked to the change log, and say so when you cannot tell. What to do, two to four actions each labeled missing page, weak page, crawl fix, or off-site, tied to rows on the ideas board or diagnosis log. New queries worth a page, terms getting impressions with nothing aimed at them. Never invent a click, an impression, a position, a CTR, a mention, or a citation. When Search Console is not connected, send one line naming the export you need and stop. Save the report dated and attach it, then deliver it to the destination the user picked as a draft first. Never post it to a channel without a yes.

## RT9 Topic watch prompt (enabledOnImport=False)

Run each weekday morning at the hour the user picked, in the timezone saved in memory. Compute the cron from that timezone. Read the ideas board, the question map, and the source map first. Then check what is new in the user's space: fresh questions buyers are asking in their category, a competitor publishing on something the board does not cover, a new thread, review, or listing in a source the AI leans on, wrong information about the user worth contesting, and a term picking up impressions in Search Console with no page behind it. Send nothing at all when there is nothing new. When there is, send one short message with the topic, the buyer question it answers, where you saw it, and one line on whether it is worth a page, a refresh, or an off-site action this week. Cap it at two topics a day. Write anything worth keeping to the ideas board so the weekly digest does not report it twice. Never invent a trend, a source, or a number. Do not write the brief unless they ask for it. Never post or reply in any community.

## RT10 Weekly prompt rerun prompt (enabledOnImport=False)

Run the Prompt rerun tracker skill on the fixed buyer prompt set from the question map. Re-ask each prompt, pull matching Search Console numbers when connected, and compare against the last saved run. Report Google and AI answers separately, non-branded rows on their own, and give a verdict on each change in the change log (worked, no change yet, hurt) with the numbers. Name the one thing to double down on. Save the run dated before analyzing. Never invent a mention, citation, position, click, or conversion. When nothing moved, send one line saying so. Never post, publish, or contact anyone from this run.

## RT11 Monthly AI visibility ledger prompt (enabledOnImport=False)

Run on the first Tuesday of the month at the hour the user picked, in the timezone saved in memory. Use the First-party AI visibility ledger skill. Re-read each platform's definition page before quoting a metric and update the dated facts register if anything changed. Pull the last 28 days and the 28 before from every connected source: Search Console generative AI report, Bing AI Performance, the analytics assistant channel, and any ChatGPT Business Hub figures the user pasted. Save the raw pulls before analyzing. Append ledger rows and add any confirmed Google update, default-model change, or reporting change to the annotations file. Post one short table: platform, metric, this window, last window, definition. Never merge platforms, never compute an AI click rate, never invent a number. For a source that is not connected, name the export needed in one line. If an update is still rolling out, say the comparison waits until a week after it completes. Deliver as a draft first.

## RT12 Monthly engine source check prompt (enabledOnImport=False)

Run on the second Tuesday of the month at the hour the user picked, in the timezone saved in memory. Use the Engine source plan skill. Read the latest prompt samples and the saved plan first. List, per engine the audience uses, the domains and source types recurring in at least a fifth of runs, and compare with last month's plan. Fetch the newest public citation-mix report and quote it with its window; never recall one. Speak up only when a source type entered or left the recurring set on an engine, or when an engine cut how many sources it lists. One line per shift: engine, what changed, which tracked prompts it touches, and the Own, Claim, Earn, or Contest action. Do not move budget on one month's shift; flag it and say the next sample decides. Update the plan file with the new check date. Never invent a share. Never post, pitch, or edit any outside source.

## RT13 Weekly inclusion and bot-access check prompt (enabledOnImport=False)

Run every Thursday at the hour the user picked, in the timezone saved in memory. Use the AI inclusion and crawler policy skill in read-only mode. Re-read robots.txt, the robots meta and X-Robots-Tag on each money page, and, where access exists, the Search generative AI setting on every property and the edge bot settings. Compare with the saved access policy. When logs are connected, run the bot log summary for the last 7 days and check that allowed bot classes received 200s on money pages. Send nothing when the state matches the policy and allowed bots are served. Otherwise send one short message: which control changed or which bot class is failing, since when, and the diff that restores the approved policy. Label every bot count unverified unless the edge provider, a published network range, or a signature confirms it. Never change a setting, a rule, or a header.

## RT14 Daily feed parity check prompt (enabledOnImport=False)

Stores only. Run each morning at the hour the user picked, in the timezone saved in memory. Use the Agentic commerce feed parity skill. Sample ten products: five by revenue rank, five at random. For each compare the feed value, the JSON-LD in the raw HTML, and the visible page text for identifier, price, currency, and availability. Say nothing when all three agree on every sampled product. On any price or availability mismatch send one short message with the product, the three values, and the likely drift source, and log the mismatch rate to the ledger. Never patch a value by hand, never submit or resubmit a feed, never change a price. Never include a gated or trade price in a message that leaves the workspace.

## RT15 Update and policy watch prompt (enabledOnImport=False)

Run each weekday morning at the hour the user picked, in the timezone saved in memory. Fetch the search status dashboard, the search platform's documentation changelog, the spam policies page, and the release notes of each assistant and reporting surface in the dated facts register. Send nothing when nothing changed. When something did, add a dated line to the annotations file, update the matching line in the dated facts register, and send one short message: what changed, the date, which skills or saved artifacts it makes stale (for example fan-out maps after a default-model change), and whether any batch waiting to publish should hold. During a rollout, say once that comparisons wait until a week after it completes and do not repeat it daily. Never speculate about what an update targets. Never recommend a site change from an update announcement alone.


## RT16 Weekly agent-readiness re-test prompt (enabledOnImport=False)

Run every Monday at the hour the user picked, in the timezone saved in memory. Compute the cron from that timezone. For each site in `websmith/profiles/` that has at least one full audit run, load `websmith-audit-runner` and run it in re-check mode, read-only (getting-started section 9): GET and HEAD only, at most 1 request per second per host, MCP `initialize` and list calls only, no logins, purchases, or form submits, no outside scan without an explicit per-domain yes for that scan. Run the AgentReady scorecard, the robot layer (robots.txt, sitemap, llms.txt, JSON-LD, feeds, dead links), and a browse-only store → product → cart pass with `websmith-browser-agent-check`, naming the engine that ran. Compare with last week's run. Report in plain words: what passed, what broke (worst first), and the ranked fixes. Deliberate owner choices stay EXCEPTION. Any failed fetch, tool, or browser step is reported first as UNTESTED with the reason. Never fix anything from this routine; offer W9's PR step instead.

Every routine prompt: compute cron from the operator's saved timezone; never publish, post, or send from a routine.


## RT17 Live discovery delta prompt (enabledOnImport=False)
Proposal only: start PAUSED, with no schedule until the operator explicitly selects one and a timezone. Load the active site's context and last discovery scorecard, use the same canonical host and fixed sample, run `live-discovery-scorecard` read-only. Save changed cells and a ranked hitlist only if there is a real delta; otherwise one dated log line. Failed requests are UNTESTED with the error. No retries into a mutating flow, no new paid trial, no source-bot schedule changes, no outbound. Report in the operator's timezone with its label.
